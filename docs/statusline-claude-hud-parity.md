# Built-in statusline and claude-hud

The built-in statusline (`agent-shim statusline`) is being brought to the feature and configuration set of stock [claude-hud](https://github.com/jarrodwatts/claude-hud) (MIT licensed). It is implemented from claude-hud's observed behaviour, not copied from its code, and the project is credited here as the specification. Anything agent-shim does not copy is recorded below with its reason.

The inventory of what claude-hud offers is read from its `src/config.ts` and held in `src/statusline/parity/inventory.ts`, at the commit named below. `node scripts/claude-hud-inventory.mts <claude-hud checkout> --check` compares it with a checkout, and a test refuses a table row for a setting agent-shim does not have. The settings themselves are listed, with their kinds, defaults and meanings, by `agent-shim statusline keys`.

Checked against claude-hud at commit `939eb66`.

## Defaults

The default statusline is a superset of stock claude-hud's default: every element claude-hud draws under its own default configuration (its `DEFAULT_CONFIG` and `DEFAULT_ELEMENT_ORDER` in `src/config.ts`) is drawn under agent-shim's, showing at least the same information, and agent-shim's own segments are drawn besides. Where claude-hud's default shows more than agent-shim's did, agent-shim takes claude-hud's. Every other difference in what is shown, in either direction, is listed below with the reason it stands: the defaults agent-shim takes from claude-hud, the differences it keeps, and the Bedrock hide, which follows what the session is rather than a setting. Differences of presentation alone (for instance the brackets round a bar, the formats of durations and token figures, the widths of bars, the separators between segments and the wording of the passed-reset state) are agent-shim's own and need no item beyond the style ones below, since each shows at least the same information. `src/statusline/parity/superset.test.ts` holds claude-hud's default elements and options and refuses a default layout or setting that drops one.

The default header is `model`, `project`, `vcs`, `provider`, `route`, `account`, `identity`, `headroom` and `extra`, and the default rows are `context`, `quota` and `addedDirs`; `preset: standard` sets the same. These follow claude-hud's defaults:

- The project segment with the added directories inline (`display.showProject: true`, `display.showAddedDirs: true`, `display.addedDirsLayout: 'inline'`), and the `addedDirs` row, which draws nothing while they are inline and is listed because claude-hud's default element order holds its added directories line.
- The version control segment, with the dirty marker and without ahead and behind (`gitStatus.enabled: true`, `gitStatus.showDirty: true`, `gitStatus.showAheadBehind: false`), straight after the project as claude-hud draws its project line.
- The extra segment, at the end of the header, since claude-hud's default draws its extra label once `--extra-cmd` gives a command; it draws nothing until `extra.command` is set.
- `usage.resetLabel: true`, from `display.showResetLabel: true`.
- `usage.modelScoped: true`, from `display.showModelScopedUsage: true`.
- `usage.sevenDayThreshold: 80`, from `display.sevenDayThreshold: 80`: a weekly window beside a five-hour one is hidden below it, as claude-hud hides it.
- `context.estimate: buffered`, from `display.autocompactBuffer: 'enabled'`.
- `context.breakdown: critical`, from `display.showTokenBreakdown: true`.
- `context.criticalAt: 85`, from `display.contextCriticalThreshold: 85`: the context bar turns red from 85% of the window, and the token breakdown, which claude-hud draws from that same threshold, appears from 85% too while `context.breakdownAt` is unset; each threshold is compared against the percentage rounded to a whole number, as claude-hud compares it, so a reading within half a point below counts as at it. `context.breakdownAt` gives the breakdown a threshold of its own, apart from the red, which claude-hud has no setting for.
- `context.warnAt: 70`, from `display.contextWarningThreshold: 70`. It is the context bar's own threshold, as `context.criticalAt` is, so `bands` colours the other bars and the context row's cache hit share, while claude-hud's context thresholds colour only its context bar.
- `model.platform: true`: the platform label after the model (`Opus 4.5 | Vertex`), which claude-hud's `formatModelDisplay` draws under every configuration, chosen from `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, a MiniMax base URL and the model ids `opusplan`, `sonnetplan` and `haikuplan` (in any case) as its `getProviderLabel` chooses it; the switches and the model ids are Claude Code's, so an Antigravity client never draws the label.

The Bedrock hide follows what the session is and is neither a default nor a setting: a Bedrock session (`CLAUDE_CODE_USE_BEDROCK` is `1`, or a model id carrying `anthropic.claude-` in any case, for any client but the Antigravity CLI, which is never one) draws no subscription window (the five-hour, weekly and per-model windows of a session that selected no provider, whether the client's payload or the identity's recorded usage supplies them) under every layout, preset and setting, as claude-hud hides its usage line then (`shouldHideUsage`) whatever its configuration. The windows describe a subscription, which a session billed by use does not spend, and agent-shim could otherwise draw the identity's recorded windows beside it. The windows of a provider the session selected, in whatever form it reports them, and a model family's are not subscription windows and still draw.

These differences are kept:

- The quota bars' bands are agent-shim's 70 and 90 (`bands`), where claude-hud colours its usage from a fixed 75% and 90% of the use rounded to a whole percentage: a threshold, not information.
- The colours are agent-shim's (the quota bars green, the model in the terminal's own colour, a quota bar's warning yellow), where claude-hud's are bright blue, cyan and bright magenta: a style.
- The labels and figures are agent-shim's (`Ctx`, `5h` and `Wk`, percentages to one decimal and without it when whole (`37%`, `37.4%`), the model without brackets, the header justified across the line), where claude-hud writes `Context`, `Usage` and `Weekly`, whole percentages and `[Opus]`: a style.
- The context figure is `both`, the tokens held over the window and the percentage, where claude-hud's `percent` is the percentage alone, and the cache hit share is drawn beside it: more information.
- The account's address is drawn whole (`account.userLength: 0`), where claude-hud cuts its user name to eight characters (`display.authUserLength: 8`), and claude-hud draws no account by default: more information.
- When the five-hour or the weekly window is at 100% to the whole number, claude-hud collapses the usage line to `Limit reached` with the reset time, keeping only the per-model windows, where agent-shim draws the windows its thresholds show, each with its own percentage and reset: more information.
- A frame claude-hud's `context-cache` rewrites is drawn as it stands here whenever the percentage of the window in use the row works out from it as it stands is above 0 to one decimal (the one decimal the row rounds the percentage of the window in use to), whatever figure `context.value` has the row write from it; claude-hud, which does not read `total_input_tokens`, rewrites every such frame by the rule `element:context` states. For a frame reporting 0 or no percentage that percentage is an estimate from `total_input_tokens` under `context.estimate` or `context.autoCompactWindow`: the tokens held are a reading of the context, and agent-shim estimates from them on every other frame too. So under `remaining` such a frame draws 100 less that estimate and under `tokens` the tokens it holds, where claude-hud draws whatever its rewrite gives the frame by the rule `element:context` states: the percentage the newest compaction left, the last good frame's figures, or the frame as it stands. For instance, for a frame holding its whole window of 200k tokens, agent-shim draws `0%` left where claude-hud draws the `70%` left of a last good frame at 30%, the `75%` left of a newer compaction that left a quarter of the window, or the `100%` left of the frame as it stands when there is neither. The speed segment reads the frame drawn, so on such a frame it measures that frame's own output tokens, or the transcript's growth when it reports none, where claude-hud measures the output tokens of the frame its rewrite gives (for instance, after a last good frame reporting 100 output tokens, a frame holding tokens and no last request draws a speed from the transcript's growth here, and no speed in claude-hud, whose restored count has not moved). A frame claude-hud rewrites whose percentage in use, as the row works it out as it stands, is not above 0 to one decimal is rewritten here as claude-hud rewrites it, apart from the differences that follow.
- A field of the frame is read here only when it is a number, and as absent otherwise, as every field of the payload is; claude-hud's `context-cache` reads a field that is missing or `null` as absent (its `?? 0`) and compares any other value as it stands. So a frame whose `used_percentage` or one of whose `current_usage` counters holds a value other than a number or `null` is rewritten here when the rest of it is a frame the rewrite takes (see `element:context`), where claude-hud draws it as it stands (for instance `0%` for a percentage of `"abc"`, `"0"` or `false`, and `NaN%` for an `input_tokens` of `"x"`); and a window other than a number or `null` is no window here, so a frame with one is not kept, gives no percentage after a compaction and is given the last good frame's window when it is restored, where claude-hud keeps the frame's own window and takes it for a window above 0 whenever JavaScript's `> 0` reads it as above 0 (a numeric string, for instance), keeping a frame with one and dividing by it. The frame itself is read the same way: a `context_window` that is not a JSON object is no frame here, so it is neither rewritten nor kept and no context row is drawn from it, where claude-hud's rewrite takes any `context_window` JavaScript reads as true: an array is rewritten as an object holding none of the frame's fields is (for instance `Context 30%` restored from a last good frame of 30%), and any other value read as true (a number other than 0, a string that is not empty, `true`) cannot take the restored fields, so claude-hud's whole render fails with an error on every frame it would restore the last good frame into.
- A number of the frame that is not finite (JSON such as `1e999` or `-1e999`, which parses to Infinity or its negative) is read as absent likewise, where claude-hud compares it as it stands: a `used_percentage` or a `current_usage` counter that is not finite leaves a frame whose rest is a frame the rewrite takes rewritten here, where claude-hud draws the frame as it stands (for instance `100%` for a percentage of `1e999`, and `100%` with the breakdown `(in: InfinityM, cache: 0)` for an `input_tokens` of `1e999`), and a window that is not finite is no window here, so such a frame is given the last good frame's window when it is restored and is drawn as it stands after a compaction or with no last good frame, where claude-hud keeps the frame's own window in all three cases, and draws `NaN%` in the last two for a window of Infinity. What is kept follows the same rule: a frame is kept here only when its percentage and its window are finite numbers above 0, and any other frame leaves the last good frame as it was, where claude-hud keeps every frame whose percentage is a number above 0 and whose window JavaScript's `> 0` reads as above 0, and writes a figure that is not finite as JSON's `null`. So a frame claude-hud keeps whose window is not finite is written there with no window, and the next frame it restores keeps its own window (for instance `60%` from a kept `60%` frame, where agent-shim restores the `30%` frame kept before it), and one it keeps whose percentage is not finite is written as a record claude-hud reads as none, so its last good frame is lost (for instance `0%`, where agent-shim restores the `30%` frame kept before it).
- The percentage a compaction left is written to one decimal, and without it when whole (`postTokens` over the window, with any fraction of a token in `postTokens` dropped first, as claude-hud drops it, so one below 1 counts as none in both), where claude-hud rounds the result to a whole percentage before drawing and keeping it, so a compaction that left less than half a percent draws `0%` there and is not kept: a style, as with the percentage of the window in use the row rounds to one decimal however it is worked out.
- A `compact_boundary` is counted here, on the compactions row and by the context row's rewrite, only when its `timestamp` is a string `Date.parse` reads as a date, as every record's timestamp is read here; claude-hud counts one whose `timestamp` is truthy and which `new Date` reads as a valid date, whatever its type. The two agree on every string, since `new Date` reads a string as `Date.parse` does, and differ exactly on a timestamp that is truthy, is not a string and that `new Date` reads as a valid date (for instance a number of milliseconds other than 0 within the range `new Date` accepts, `true`, which it reads as 1, or an array whose text is a date), which claude-hud counts on both, drawing the percentage it left, and agent-shim does not count. Claude Code writes every timestamp as an ISO 8601 string, and the statusline reads every record's timestamp the same way, so its rows never disagree about which records are stamped.
- The newest compaction is the one the transcript reader has seen: while it is catching up with a transcript too big to read at once it has read the start and the newest window of it, where claude-hud reads it whole, so a compaction in the part between is missed until the reader reaches it. Until then a frame it would rewrite is rewritten from what the reader has seen, by the rule `element:context` states (as the last good frame, as the percentage an earlier compaction left, or as it stands, as the case may be), where claude-hud, which reads the whole transcript, rewrites it by the same rule with the missed compaction as the newest (so, by that rule, as the percentage the missed compaction left, or as it stands when that compaction recorded no finite token count of 1 or more or the frame reports no window above 0, or as the last good frame when the compaction guard, as the next bullet sets out, does not count it). Once the reader reaches it, the missed compaction is weighed as it would have been from the start, against the reading behind the last good frame: a restored frame written back keeps the time of the reading it came from, and a frame given an earlier compaction's percentage is kept with that compaction's time, so neither hides it. The frame right after a compaction has the compaction at the end of the transcript, in the newest window.
- The compaction guard compares a compaction's time with the time of the reading the last good frame came from, which a restored frame written back keeps and which, for a frame given a compaction's percentage, is that compaction's time, where claude-hud compares it with when its cache file was last written, which writing either frame moves on to the time of the write. This is what lets a compaction the reader reaches late count once it is read. So agent-shim counts a `compact_boundary` stamped later than the reading behind the last good frame, and claude-hud counts one stamped later than the last write of its record: they decide differently exactly on a boundary stamped later than one of those two times and at or before the other, which agent-shim counts when it is later than the reading and at or before the write, and claude-hud counts when it is later than the write and at or before the reading (a reading stamped ahead of the write, as a compaction stamped ahead of the clock leaves it).
- A last good frame last written more than 7 days ago is read as none (one stamped later than the present, as a clock set back leaves it, is drawn, as claude-hud draws it), where claude-hud removes such a file in a sweep it tries at random on one in a hundred of the frames that pass the test a frame it keeps must pass, whether or not its write limit lets that frame be written, and until the sweep has run takes the file for the transcript's last good frame as it takes a record of any age, so a frame it would rewrite is given the file's figures unless its compaction guard (the bullet before) counts the newest compaction, and is then given that compaction's percentage or drawn as it stands, by the rule `element:context` states. The records are limited to the 100 whose files have the latest modification times whenever a write is attempted for a transcript whose record's path holds no regular file, where claude-hud enforces the same limit, by the same modification times, only in that sweep, so it can hold more than 100 records until the sweep runs and take one agent-shim has removed for a transcript's last good frame. A write sets a file's modification time to the clock's time in both, so once the clock is set back behind the times of the records already at the limit, the record just written for a transcript whose record's path held no regular file has the earliest time and is removed at once here, as claude-hud's sweep removes it when the sweep runs on that frame (for instance, with 100 records written an hour ahead of the clock, a frame at 30% for a new transcript and then a frame the rewrite takes draw `0%` here, where claude-hud draws `30%`, or `0%` when its sweep ran on the first frame). The record is kept under agent-shim's statusline state, where claude-hud keeps it under its plugin directory, so the two never read each other's; both key it by the transcript path with the white space around it removed, resolved against the directory the statusline runs in. A file of the statusline's own state (the cost ledger, the context records, the speed samples and the transcript reader's cache) is read only when it is a regular file once its links are followed, and as absent otherwise, where claude-hud reads whatever is at the path of each of its own, so a FIFO at one holds claude-hud's render until something opens the FIFO for writing and closes it again; the settings files the output style is read from are read as claude-hud reads them, a FIFO included. The statusline writes each file of its state whole and renames it into place, so a symbolic link or a FIFO at its path is replaced when a write is due, where claude-hud writes its context record and speed sample through the path: into the file a link names, and into a FIFO, which holds claude-hud's render until something opens the FIFO for reading. The context record's write limit reads the time of what the path names, a link followed, in both, so on a good frame with a FIFO at the record's path the two differ exactly when the FIFO was last modified 3 seconds or more before the clock.
- A last good frame's record is read only in the shape agent-shim writes, and as none otherwise, as a record that is not JSON is read in both: its two times and its percentage numbers (any finite percentage, a negative one included, which claude-hud restores too, both then drawing the frame as one reporting no percentage), its tokens held and window numbers or absent, its last request absent or an object of the four counters, each a number or absent, and no field beyond these, at the top or in the last request. claude-hud reads any JSON object whose `used_percentage` is a finite number and takes its other fields as they are, so it restores a record outside that shape, such as one an earlier release wrote, one with a field missing that agent-shim's shape requires (one with no `saved_at` giving way to any compaction) or one with a field added. Until the next frame that is kept (see `element:context`) writes the record again, a frame the rewrite would restore from such a record is given the newest compaction's percentage or drawn as it stands: the record's two times are what the age limit and the compaction guard weigh, and a record not in the shape that carries them is not one agent-shim can weigh.
- A session token total too large for a number, a sum past the largest finite one, is drawn as `InfinityM` on every refresh, as claude-hud draws it on the refresh that reads its transcript afresh; claude-hud's transcript cache writes such a total as `null`, so each later refresh it serves from that cache draws the total as 0 (`Tokens 20 (in: 0, out: 20)` for two responses of `1e308` input tokens and 10 output tokens each), where agent-shim's cache reads `null` back as the Infinity it was written from: the figure stays the one the transcript gives.
- The tokens held are read from `context_window.total_input_tokens`, which Claude Code documents as the sum of the last request's input and cache tokens, where claude-hud sums `current_usage`: the two agree on every payload that follows the documentation, and a payload that omits `total_input_tokens` or whose two figures disagree is estimated from `total_input_tokens` alone, so one without it draws the percentage it reports (a 0 included) as it is, or no row when it reports none, where claude-hud estimates from `current_usage`; a frame the rewrite takes (see `element:context`) is rewritten first, as it is in claude-hud. Where neither source gives a percentage to draw for the frame drawn, a frame the rewrite gives a last good frame's figures included (one restored from a record holding a negative percentage, which both read as none, and no tokens held, for instance), claude-hud draws a `Context` row at 0% and agent-shim draws no context row, a row at 0% of an unknown share carrying no information.
- A window with no reset time is drawn with `available` beside it, where claude-hud draws no reset text: a stated reading of a reset that is not pending.
- The quota windows come from the payload, else the identity's recorded usage, where claude-hud draws only the payload's, and a session that selected a provider draws that provider's windows in place of the payload's five-hour, weekly and per-model ones, which describe an account the session does not spend: more information in the first case, and the windows the session actually spends in the second.
- The context and quota bars share a line through `layout.mergeBars`, where claude-hud names them as a merge group; either joins them when they fit.
- The project path, the added directories and the branch are plain text, where claude-hud wraps them in terminal hyperlinks: the text drawn is the same and only the link targets differ, which agent-shim leaves out to keep the line's width exact and to spare the remote lookup; see [Project and version control](#project-and-version-control).
- The provider, route, account, identity and headroom segments are agent-shim's own, drawn after the version control segment.
- A client that sends no display name, or a blank one, is named by its model id, trimmed and otherwise as it stands, as claude-hud falls back, where claude-hud rewrites a Bedrock id (`us.anthropic.claude-opus-4-5-20251101-v1:0`) or an id it labels Enterprise (`opusplan`) into a readable name (`Claude Opus 4.5`, `Claude Opus`): the id carries everything the readable name does and more (the region, the date, the version suffix), so the rewrite is a style.
- A client that names no model by any route (no override, no non-blank display name or model id, and no transcript name that `model.source` supplies, or a name that `model.format` leaves empty) gets the platform alone (`Vertex`), and nothing when no platform is detected, where claude-hud draws the word `Unknown` (`[Unknown | Vertex]`, `[Unknown]`): the placeholder carries no information.

A statusline configured by someone relying on the default before it became a superset draws more now, aligns the context bar and the quota windows each within itself where the added windows and reset words stop the quota windows fitting on one grid with the context bar (the previous default lined them up wherever it fitted them on one grid), turns the context bar red from 85% of the window rather than 90%, hides a weekly window beside a five-hour one until its use, rounded to a whole percentage, reaches 80%, and draws no subscription window for a Bedrock session. The previous output is `layout.header` set to `model`, `provider`, `route`, `account`, `identity` and `headroom`, `layout.rows` set to `context` and `quota`, `usage.resetLabel`, `usage.modelScoped` and `model.platform` set to `false`, `usage.sevenDayThreshold` set to 0, `context.estimate` and `context.breakdown` set to `never`, and `context.criticalAt` set to 90, where the context bar turned red before. A layer that set `bands.warnAt` or `bands.criticalAt` and relied on the context bar following them sets `context.warnAt` and `context.criticalAt` to the same values, since the context bar has thresholds of its own now and the two must stay in order: setting only `context.warnAt` to 85 or more, or only `context.criticalAt` to 70 or less, is refused now; most such values were refused when the context bar followed `bands` as well, but a lone `context.warnAt` from 85 to 89, and a lone value that was in order against a layer's own `bands`, were accepted while the other fell back to `bands`; an `AGENT_SHIM_STATUSLINE` written when the context bar followed `bands` meets the same refusal when its lone value is out of order against the other's default, and one that sets neither threshold draws the red from 85 now. The context bar's colour and the breakdown's start, and the quota row's `usage.threshold` and `usage.sevenDayThreshold`, compare the whole-number percentage with the thresholds, as claude-hud does, where the previous default compared the fraction, so no setting restores that: a reading within half a point below a threshold counts as at it, and a cache hit share exactly on a whole-percentage edge of the bands is on the side it reaches, where the previous default could put it on the other side through floating-point rounding (a share of exactly 10% under the default bands is red, where it was yellow). A negative `total_input_tokens` is read as absent too, where the previous default drew it as a token count of its own (negative, or rounded to zero), beside the percentage the client reported, and no setting restores that either; a negative `used_percentage` is read as absent too, where the previous default drew it as a negative percentage beside an empty bar, and one above 100 is drawn as 100, where the previous default drew it as sent; and on a line too narrow to draw the quota windows one to a row with their labels and figures padded to match, each window is drawn aligned within itself, with a bar that fits the line widened to take its spare width, where the previous default drew every bar at its base size, with the labels padded to match. To keep the breakdown but start it where it started before, at 90%, set `context.breakdownAt` to 90, which leaves the red at 85%, or `context.criticalAt` to 90, which moves both. Two things those settings do not undo, because they follow what the session is and not a preference: a Bedrock session (`CLAUDE_CODE_USE_BEDROCK` is `1`, or a model id carrying `anthropic.claude-` in any case, for any client but the Antigravity CLI, which is never one) never draws a subscription window (the five-hour, weekly and per-model windows of a session that selected no provider) whatever the settings, where the previous default drew the windows the payload or the identity's recorded usage supplied, although they do not apply there, and a client whose display name is absent, not text, blank or padded with white space is named by its display name without the padding when that has any text, else by its model id when it has one, and has no model segment otherwise, where the previous default drew no model for an absent name, the blank text as sent for a blank one and the padding as sent.

## Project and version control

The `project`, `vcs`, `addedDirs` and `gitFiles` elements read the working directory from the client's payload (`cwd`, else `workspace.current_dir`) and run `git` and `jj` without a shell through the statusline's ports, each bounded in time and output. The vcs segment asks git for the fewest things the settings need: one command for the branch alone, or one that reads the branch, the upstream's ahead and behind counts, dirtiness and the changed files together, and further ones only for what is drawn: the lines changed, the repository root to order the changed files by when they were modified, and a name for a detached HEAD. claude-hud runs a command for each of the branch, the status, the ahead and behind counts and the remote.

Two behaviours of claude-hud have no setting and are not reproduced. It wraps the project path, the added directories, the branch and each changed file in terminal hyperlinks (a `file:` link, and a GitHub link built from the `origin` remote); agent-shim draws them as plain text, which keeps the line's width exact and spares the remote lookup. On Windows it runs git through a long-lived worker process so that it can end a hung command's process tree; agent-shim's bounded run port ends the command it started and uses the same path on every platform.
## Cost and machine information

A direct session's cost is the client's own `cost.total_cost_usd`, drawn as `Cost`. Where the client reports none (an older client, or before the first response), the door's usage log stands in: every request the door served for the conversation is priced from the per-model prices `agent-shim model price` stores, keyed `<provider>/<model>`, with cache writes and reads priced at Anthropic's published ratios of the input price, and drawn as `Est.`. A request whose model has no configured price makes the whole estimate absent, since a total that left a request out would read lower than the bill. A conversation is the client's own session id, which the door records from each request's header beside the launch's id, because clearing the conversation starts a new id and a new client cost inside one launch; a client that sends no id gets no estimate. agent-shim ships no price table, so an estimate exists only for models the person has priced.

A routed session's own figure is not a bill, so claude-hud hides it for Bedrock and Vertex model ids unless `showRoutedCost` is set. agent-shim treats a launch that selected a provider the same way, and `cost.routed` opts in. Where the door served the session, its own record of each request is the more accurate source, so it is preferred over the client's figure; the client's figure is used only when the door gives none and it is above zero.

Today's spend is a ledger of the conversations the statusline has drawn, in the statusline's state directory under the agent-shim home: one file for each conversation for each local day, summed on read, so conversations drawing at the same moment cannot overwrite one another. Like claude-hud's, it counts a conversation from its first sighting and resets at local midnight. A conversation that was drawn on the day before, within the last day, starts the new day from the total it had then, so the spend between its last render and its first of the new day counts towards the new day, because nothing says where in the gap it fell. Days before the one preceding today are removed, and a day dated after today (the clock was set back) is left alone. A conversation is bound to the source of its first figure (the client's, or the door's estimate), and a figure from the other source is not counted. So a routed conversation that started on the door's estimate, and later shows the client's own figure because the door has no complete estimate (a switch to an unpriced model, say), stops adding to Today from then on, keeping what it had added, while the cost segment draws the new figure on its own scale. It records whichever cost the conversation shows, so a routed session contributes only when `cost.routed` is set.

The environment row reads a configuration file only up to a fixed size (a global file over it holds nothing for the row, so servers and hook events only it names are not counted), because each draw parses what it reads whole. It counts as claude-hud does (one for each CLAUDE.md file, each Markdown file under a rules directory, each MCP server per scope and each hook event) and differs in three ways: it pluralises its labels, a project `.claude` directory that is the user's own is read once, wholly as the user scope, and a directory named `CLAUDE.md` or `CLAUDE.local.md` (or a link to one) is not counted, where claude-hud counts whatever exists at the path, since a directory holds no instructions for Claude Code to read. Both count anything else at those paths, a FIFO included, and count an entry under a rules directory only when its name ends in `.md` and it is a regular file once its links are followed. The output style and MCP error names that claude-hud draws on the same line are accounted for under `display.showOutputStyle` and `display.showMcp`.

## Language

The words the statusline writes live in one catalogue, keyed by stable ids, in `src/statusline/messages/`: English is the default and the reference, and Chinese is written in simplified and in traditional characters. A test refuses a catalogue that lacks an id English has or uses other placeholders, and another refuses a word written in a module instead of the catalogue. The wording was written independently of claude-hud's translations and may coincide with them where the vocabulary is standard. A label's colon and the space after it are part of its message, and a list is joined with the language's own separator, so Chinese uses its full-width colon and comma; the pipe and the bar that separate segments and rows, the parentheses around a figure and the middle dot that joins a segment's parts are layout and the same in every language, as are the units of a duration. What stays the same in every language is deliberate: durations (`1h 30m`), token counts (`634k`), money (`$1.25`) and product names. A wall-clock time follows the system locale and `clock.hourCycle` and `clock.seconds`, so it is not the language's to decide.

claude-hud reads `zh` as simplified and `zh-TW` as traditional Chinese, and falls back to English for any other value. agent-shim reads those two tags the same way and keeps the canonical tag, `zh-Hans` or `zh-Hant`, so a hand-copied claude-hud `language` works, but refuses any other value instead of falling back to English, as it does for every setting.

## Presets

claude-hud's presets exist only in its guided configuration flow (`commands/configure.md`), which applies a bundle of display toggles to a configuration. agent-shim has them as a setting: `preset` names a bundle of `layout.header`, `layout.rows`, `git.*`, `jj.*`, `usage.resetLabel` and `context.breakdown` that the layer sets beneath the keys it names itself and above everything the shallower layers set, so any key still overrides a preset and a deeper layer's preset replaces what a shallower layer chose. Every preset sets the same keys, so choosing one leaves nothing of another behind. `preset: standard` is the statusline's own default, claude-hud's default display with agent-shim's own segments (see [Defaults](#defaults)), and is there so a deeper layer can go back to it. Each of the other presets is a claude-hud configuration with that preset applied, read element by element from its definition, so a toggle the definition leaves out is at claude-hud's default.

claude-hud's text calls Minimal "core only" and "the default", but its definition keeps git on and leaves the project, the added directories, usage and the token breakdown at their defaults, which are on. agent-shim follows the definition: Minimal draws the project and version control, and turns usage off, as the definition says. The provider, route, account, identity and headroom segments are agent-shim's own, so `preset: standard` draws them and claude-hud's presets do not; the daily cost, the speed, the changed-files line and the session times are agent-shim's own or settings of claude-hud that no preset turns on, so only a layout that names them draws them. claude-hud has no "show everything" preset, so agent-shim has none.
## Activity

The `tools`, `skills`, `mcp`, `agents` and `todos` rows are read from the session's transcript by the same reader that serves the other transcript elements, folded from the same lines. The tool calls, agents and todo list are the newest state of something, so they are also read from the last window of a transcript that is still being caught up: the tools and agents are then that window's alone, never joined to the part read so far, and the todo list is the window's when it holds a `TodoWrite` and empty otherwise; the skills and servers add up over every record. A tool call is paired with its result by id and is running until it has one, within the limits the tools and agents rows state. The transcript names the calls of a subagent too, and the reader leaves those out, since a subagent's calls are its own.

## Custom line and extra command

The custom line is the person's own text, drawn above the header or below the last row. The extra segment runs a program and draws what it prints. That is code execution with the person's privileges on every refresh, which claude-hud guards with an environment opt-in, because its command comes from a command-line argument in a settings file that may be shared. Here the guard is where the command may come from: `extra.command` can be set by exactly these: the global config, a configuration profile, a directory rule, and a command-line assignment (which writes one of the others). The global config, the profiles directory and the directory rules are files under the agent-shim home that only the person writes. A profile is found only by name in the home's `config-profiles` directory, and every name in a configuration file is held to a rule that stops it naming a path. A project file, `.agent-shim.json` or `.agent-shim.local.json` or either of the legacy names, may only name a profile by the strict shape new names are given, but a profile it names may be one the person has stored under a looser name, and may extend one: the person wrote them all, so a project file can select among the person's own profiles but cannot supply a program. A project file that sets `extra` itself is refused with an error naming the file, because a cloned repository would otherwise choose the program a launch runs. The door's config API, which can write profiles, refuses the extra settings for the same reason: a delegated writer, an MCP agent or the web client with the writes grant, must not choose a program a launch runs, the same rule that keeps credential commands and provider environment entries out of the API. The command is a list of arguments, so nothing in it is a shell's to interpret. It runs in the session's working directory through the same port every program the statusline starts goes through, which bounds its time and its output. What it prints is split into words at its white space controls (a tab, a carriage return) and line and paragraph separators and joined by single spaces. It is cleaned of escape sequences, the other control characters and anything that draws nothing, and cut to the length of other text from outside the statusline. The command is also not run unless `extra` is listed in `layout.header`. A command that fails, takes too long or prints nothing draws nothing. When it takes longer than the limit it is killed with SIGKILL, which it cannot trap; a process it started stays running, because the synchronous API the ports use cannot signal a process group, and it does not hold the line, because the program's output goes to a private temporary file that is removed afterwards, not to a pipe a leftover could keep open. That file is capped by `ulimit -f` on systems that have it, which bounds every file the program writes and every process it starts, so a program that writes a large cache is stopped and draws nothing, and so does one whose output reaches the limit, whichever size of block the shell counts it in; on Windows only the time limit bounds it. A refresh cancelled by a newer update leaves the program running until it exits and a directory that the next refresh sweeps. Only the extra command is run this way: git and Jujutsu keep a pipe and no limit. The command inherits the statusline's whole environment, which is Claude Code's: it can include the launch's credential variables, its headers and its proxy settings. Nothing is scrubbed, because the command is the person's own program run with their privileges, which needs `PATH`, `HOME` and the proxy settings to behave as it does in their shell, and a list of variables to remove would be a guess; claude-hud inherits in the same way. A command should not log its environment.
